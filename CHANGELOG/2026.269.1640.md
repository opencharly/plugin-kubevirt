# 2026.269.1640 — fix(kubevirt): `wait-ready` asserts the KubeVirt + CDI platform CRs

fix(kubevirt): `wait-ready` asserts the KubeVirt + CDI platform CRs

**R1 — the verb could not express the platform readiness the R10 bed requires.**

## The anomaly

The KubeVirt-integration plan's R10 bed (`check-kubevirt-operator`, `charly/charly.yml`)
installs the KubeVirt + CDI platform and then asserts — in the plan's own words — a
`kubevirt:` probe that the **KubeVirt CR** and the **CDI CR** report `Deployed`
(plan §WS-6.2/§5). The verb's `wait-ready` method only ever waited on a
**`VirtualMachineInstance`**:

```go
u, err := client.Resource(gvrVMIs).Namespace(ns).Get(ctx, in.Name, ...)
if err == nil && vmiReady(u.Object) { return "… Ready" }
```

A platform-only bed has no VMI to name, so the plan's `kubevirt: wait-ready` on the CRs
could not be expressed at all — the run at `2026.269.1334` had to fall back to the
`kube:` verb's generic `wait-ready`, which rejects the CDI CR outright
(`unsupported kind "CDI"`), because the CR is a KubeVirt/CDI-native resource the
Kubernetes-generic probe has no model for. That is a genuine verb gap, not a bed error.

## The fix

`wait-ready` gains a **platform arm** selected by the CR's **canonical install
namespace** (`namespace: kubevirt` → the `KubeVirt` CR; `namespace: cdi` → the `CDI`
CR). It polls `status.phase` to `Deployed` and names the observed phase on a timeout.
Any other namespace keeps the **VMI arm** byte-identically (waits for the named
`VirtualMachineInstance` to report `Ready`).

The selector is the namespace alone, which is exactly what a platform bed has: the
platform CRs are always named after their kind (`kubevirt`, `cdi`) in their canonical
install namespaces, and there is no VM to name. The platform arm therefore also
**waives the `name` required-modifier** (the CR name is derived from the namespace),
while the VMI arm still requires it. Both arms share one dynamic client and one phase
read (R3).

## Summary of changes

- **`candy/plugin-kubevirt/methods.go`** — `runWaitReady` gains the platform arm
  (`platformCR` table + `platformCRForNamespace` + `platformWaitReady` +
  `waitPlatformCRReady`); `dispatch` waives the `name` required-modifier for the
  platform arm; the VMI arm is unchanged.
- **`candy/plugin-kubevirt/cluster.go`** — the CDI CR GVR (`gvrCDICRs`) joins the
  canonical GVR table beside the existing `gvrKubeVirtCRs`.
- **`candy/plugin-kubevirt/dispatch_test.go`** — cluster-free unit tests pinning the
  namespace selector and the `name`-waiver.
- **README.md** — documents the two `wait-ready` arms.
