# 2026.296.2001 — feat(kubevirt): render devices.host_devices as spec.domain.devices.hostDevices

## Summary

A KubeVirt guest gets its own `/dev/kvm` only through **host-device
passthrough** — a CPU feature alone is not enough. The schema half landed as
`opencharly/spec#277` (`#KubevirtDevices.host_devices`, tag `v0.2026296.1338`);
this PR is the renderer half.

- `candy/plugin-kubevirt/render.go` now renders `devices.host_devices` onto
  `spec.template.spec.domain.devices.hostDevices`, mirroring the existing
  `Devices.Disks` loop: `deviceName` is required, and the optional guest `name`
  is omitted when unset so KubeVirt's own default (`deviceName`) applies.
- Lockstep module bump: `spec` → `v0.2026296.1338` (the first tag carrying
  `Host_devices`) and `sdk` → `v0.2026296.1207`. Spec could not move alone:
  the older `sdk v0.2026286.932` aliases spec types that were removed since
  `v0.2026287.638` (`KubernetesGatewayAPI`, `KubernetesResources`, …), so the
  build failed with `undefined: spec.KubernetesGatewayAPI` until SDK moved too.
- Documented the nested-virtualisation authoring (`cpu.model:
  host-passthrough` + `devices.host_devices: [{device_name: kvm, name: kvm}]`)
  in the `kubevirt` skill body and the candy description.

This is the producer-first leg of the nested-KVM CI work tracked in
`opencharly/opencharly#607` (the four blacksmith Ubuntu tiers follow in
`distro-ubuntu`, then one tier is redeployed and proven live).
