# 2026.295.2057 — fix(kubevirt): emit domain.cpu cores/sockets/threads flat, not nested topology

## Summary

`renderCPU` emitted the CPU topology as a nested object (`domain.cpu.topology.{cores,sockets,threads}`).
KubeVirt's CPU type takes those fields **flat**; it prunes the unknown `topology` field and defaults
the guest to **one core**. Every `kind:kubevirt` deploy that requested `cpu.cores` silently ran
under-provisioned. The renderer now emits `domain.cpu.{cores,sockets,threads}` and the render test
asserts that shape (and rejects a nested `topology`).

## Root cause analysis (R1)

**Symptom, measured on `ci-runner-vmi-1`** — a `githubrunner-ubuntu-vmi` template declaring
`cpu: { cores: 16 }`, memory 32G:

```
$ kubectl apply ... (charly deploy add ci-runner-vmi-1)
Warning: unknown field "spec.template.spec.domain.cpu.topology"

$ kubectl get vmi charly-ci-runner-vmi-1 -o jsonpath='{.spec.domain.cpu}'
{"cores":1,"maxSockets":4,"model":"host-model","sockets":1,"threads":1}

$ ssh charly-ci-runner-vmi-1 'nproc; free -g | head -2'
1
               total        used        free
Mem:              29           2          17
```

**Mechanism.** `renderCPU` (render.go) built `out["topology"] = {cores,sockets,threads}`. KubeVirt's
`VMI.spec.domain.cpu` is a flat struct (`cores`, `sockets`, `threads`, `model`,
`dedicatedCPUPlacement`, `maxSockets`); there is no `topology` member. The API server prunes unknown
fields on admission, so the request was accepted with the topology discarded and the guest defaulted
to one core. Memory is a separate path (`domain.resources.requests`), which is why the VM looked
correctly sized in every other respect.

**Missed control.** `render_test.go` asserted the nested shape (`cpu["topology"].(map[string]any)`),
so the unit test **encoded the defect**; and no bed asserted the guest's CPU count — the
`check-githubrunner-ubuntu-vmi` bed asserts the runner binary and the docker socket, not `nproc`.
That is the control this change repairs (the test now asserts flat fields and fails on a nested
`topology`).

**Blast radius.** Every `kind:kubevirt` deploy with `cpu.cores`, on any cluster. The defect is in the
rendered document, not in a venue: it silently under-provisions rather than erroring.

**Root fix.** Emit the flat fields; assert the emitted document shape. The live confirmation is a
redeploy of the affected fleet once this is merged and pinned (the guest must report `nproc` equal
to the template's cores).
