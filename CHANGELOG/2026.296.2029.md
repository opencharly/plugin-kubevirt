# 2026.296.2029 — docs(kubevirt): correct the host_devices claim — it is not the /dev/kvm route

## Summary

Correct the `host_devices` prose introduced by `#43` (and the renderer's own
comment): **`spec.domain.devices.hostDevices` is not the route to a guest
`/dev/kvm`.**

Measured on `quant-dev`:

- A VMI carrying `devices.hostDevices` is rejected at admission:
  `The request is invalid: spec.HostDevices: Host Devices feature gate is not
  enabled in kubevirt-config` (the `HostDevices` gate is Alpha and off). The
  host-device address pools are PCI/MDEV/USB only, so a device-plugin resource
  cannot carry a character device.
- A guest's `/dev/kvm` comes from **`cpu.model: host-passthrough`**: the guest's
  own kernel loads `kvm_amd`/`kvm_intel` and creates the device. Proven live on
  `ci-runner-2vcpu-1`: `svm` in `/proc/cpuinfo`, `/dev/kvm` (`root:kvm` 0660),
  `kvm_amd` loaded, and a nested `qemu-system-x86_64 -accel kvm` exited 0.

The change is comments/ prose only:

- `candy/plugin-kubevirt/render.go` — the host-device loop comment now says
  PCI/MDEV/USB passthrough and names `host-passthrough` as the nested-virt route.
- `candy/plugin-kubevirt/charly.yml` — the candy description no longer calls
  `host_devices` "the only route to a guest /dev/kvm".
- `.agents/skills/kubevirt/SKILL.md` — the host-device section now separates the
  two mechanisms, with an accurate PCI example and the measured nested-virt
  recipe.

The renderer's behaviour is unchanged; the `host_devices` field remains the
correct rendering for real PCI/MDEV/USB passthrough.
